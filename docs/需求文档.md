## 1. 项目背景与目标

### 1.1 背景

校园二手教材存在三个典型问题：

- 每学期教材需求集中爆发，新书价格高，旧书大量闲置。
- 交易分散在微信群、二手平台，信息零散，缺乏成色、价格、卖家信誉的结构化描述。
- 线下交易缺少统一的状态跟踪与交接凭证，容易出现“书被重复卖出”“付款后找不到人”“纠纷无记录”等问题。

### 1.2 产品目标

书接力面向同一校园内的学生，提供二手教材的发布、检索、下单、支付、线下交接、互评与纠纷处理闭环。

核心目标：

1. 让卖家在 3 分钟内发布一本教材。
2. 让买家通过关键词/分类快速找到教材并完成下单。
3. 用订单状态机、书籍锁和交接码，保证“一本书同一时间只能卖给一个人”。
4. 用双向评价、举报与后台处理，形成可追溯的校园交易信用。
5. 用单机 SQLite + 零构建前端，保证项目可直接运行、便于课程验收。

### 1.3 成功指标（课程项目口径）

| 指标 | 目标 |
|---|---|
| 核心交易闭环 | 发布 → 审核 → 下单 → 支付 → 交接 → 收货 → 评价全部可完成 |
| 状态一致性 | 非法状态转移 100% 被拒绝并返回明确错误码 |
| 超卖 | 同一本书同一时间最多一个有效订单 |
| 权限隔离 | 非交易方不可查看/操作订单；非管理员不可审核、封禁、处理退款 |
| 可运行性 | `pip install -r requirements.txt && python run.py` 可直接启动 |
| 测试 | 自动化测试全部通过，核心链路覆盖率不低于 80% |

## 3. 范围

### 3.1 本期范围

- 单校园场景，不做跨校交易。
- 站内信通知，不做短信/邮件通知。
- 模拟支付（校内卡、模拟第三方），不接真实支付网关。
- 校内线下交接（图书馆西门、宿舍楼下、校园快递点），不做真实物流轨迹。
- SQLite 单机数据库，单实例部署。
- 服务端渲染页面 + 原生 JavaScript，不做 Vue/React 工程化前端。

### 3.2 明确不做

- 真实资金清算、退款回银行卡、分账。
- 邮件/SMS 推送、微信通知。
- 申诉工单、人工仲裁的多级流转。
- 评价/用户的举报页面入口（API 已支持，页面仅提供书籍举报）。
- 多卖家购物车、合并支付、优惠券、积分。
- 微服务、容器编排、Redis 缓存、对象存储。

## 4. 核心业务流程

### 4.1 主流程（Happy Path）

```text
卖家发布教材
  → 管理员审核通过
  → 买家搜索/浏览并下单（锁书 30 分钟）
  → 买家支付（模拟）
  → 卖家确认交接点，系统生成 4 位交接码
  → 双方线下见面，买家核对交接码
  → 买家输入交接码确认收货
  → 订单完成，双方互评，信誉分更新
  → 完成满 30 天自动关闭
```

### 4.2 异常流程

| 场景 | 系统行为 |
|---|---|
| 下单后 30 分钟未支付 | 定时任务自动取消订单，释放书籍锁，通知双方 |
| 买家主动取消待支付订单 | 订单 `CANCELLED`，书籍回到 `ON_SALE` |
| 支付金额与订单金额不一致 | 支付失败，返回 `PAYMENT_FAILED`，订单仍为 `CREATED` |
| 重复支付 | 返回 `409 ORDER_STATE_CONFLICT`，不产生第二笔支付流水 |
| 买家输错交接码 | 返回 `422 HANDOVER_CODE_MISMATCH`，订单仍为 `SHIPPED` |
| 支付后 48 小时内未交接申请退款 | 进入 `REFUNDING`，等待管理员审批 |
| 交接后 48 小时内申请退款 | 必须填写纠纷说明，进入 `REFUNDING` |
| 管理员同意退款 | 订单 `REFUNDED`，支付流水标记退款，书籍下架 |
| 管理员驳回退款 | 订单回到 `PAID`，交易继续 |
| 书籍被举报且管理员判定成立 | 书籍 `BANNED`，卖家收到通知；历史订单不受影响 |
| 卖家被管理员封禁 | 旧会话立即失效，无法继续操作 |
| 同一本书被第二个买家下单 | 返回 `409 BOOK_ALREADY_LOCKED`，不创建订单 |

## 5. 功能需求

需求编号规则：`FR-模块-序号`。优先级：P0 必须实现，P1 应该实现，P2 可延后。

### 5.1 身份与账号（FR-AUTH）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-AUTH-01 | 邮箱 + 密码注册 | P0 | 邮箱唯一；密码至少 8 位；昵称 2–20 字；注册成功自动登录 |
| FR-AUTH-02 | 登录/登出 | P0 | 正确凭证登录成功；错误凭证统一提示“邮箱或密码错误”；登出后受保护页面不可访问 |
| FR-AUTH-03 | 找回密码 | P0 | 校验邮箱 + 安全问题答案后可设置新密码；答案错误不泄露账号是否存在 |
| FR-AUTH-04 | 修改密码 | P1 | 校验原密码；新密码至少 8 位 |
| FR-AUTH-05 | 个人资料 | P1 | 可修改昵称、学号；展示信誉分、完成交易次数、收到的评价 |
| FR-AUTH-06 | 账号封禁 | P0 | 管理员可封禁/解封学生；封禁后旧会话立即失效；不能封禁管理员 |

**业务规则**

- 密码使用 bcrypt 哈希存储，任何接口不返回密码哈希或安全问题答案哈希。
- 会话使用 HttpOnly 签名 Cookie，默认 7 天有效；生产可通过环境变量开启 `Secure`。
- 未登录访问受保护页面跳转登录页；API 返回 `401 UNAUTHORIZED`。
- 被封禁用户访问受保护资源返回 `403 ACCOUNT_BANNED`。

### 5.2 书籍目录（FR-BOOK）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-BOOK-01 | 发布教材 | P0 | 必填书名、分类、成色、价格；价格以“元”输入，后端转整数分；发布后状态 `PENDING_REVIEW` |
| FR-BOOK-02 | 编辑教材 | P0 | 仅卖家或管理员；封禁书籍不可编辑；校验同创建 |
| FR-BOOK-03 | 上传封面 | P1 | 支持 JPG/PNG/GIF/WEBP；最大 2MB；文件名由服务端生成，防路径穿越 |
| FR-BOOK-04 | 上下架 | P0 | 卖家可下架 `ON_SALE` 书籍；可重新上架 `OFF_SHELF`；已售 `SOLD` 可再次出售 |
| FR-BOOK-05 | 分类与搜索 | P0 | 按分类筛选；按书名/作者/ISBN 关键词搜索；支持最新、价格升序、价格降序 |
| FR-BOOK-06 | 书籍详情 | P0 | 展示书名、作者、版次、ISBN、成色、价格、描述、卖家昵称/信誉/交易次数 |
| FR-BOOK-07 | 管理员审核 | P0 | 待审核书籍可通过或驳回；驳回需填写原因并通知卖家；通过后上架 |
| FR-BOOK-08 | 封禁/解封 | P0 | 管理员可封禁违规书籍；解封后回到 `OFF_SHELF`，由卖家决定是否重新上架 |
| FR-BOOK-09 | 状态筛选权限 | P0 | 未登录查询非 `ON_SALE` 状态返回 401，学生返回 403；管理员可查询待审核/封禁等状态 |

**业务规则**

- 书籍状态：`DRAFT`（预留）、`PENDING_REVIEW`、`ON_SALE`、`LOCKED`、`SOLD`、`OFF_SHELF`、`BANNED`。
- 只有 `ON_SALE` 书籍可被下单；下单成功即 `LOCKED`。
- 取消/超时后 `LOCKED` 回到 `ON_SALE`；确认收货后 `LOCKED` 变为 `SOLD`。
- 退款成立后书籍下架为 `OFF_SHELF`。
- 买家可查看自己正在交易或曾下单的书籍详情，即使该书已锁定/下架。

### 5.3 订单（FR-ORDER）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-ORDER-01 | 创建订单 | P0 | 不能购买自己的书；仅 `ON_SALE` 可下单；锁书 30 分钟；生成唯一订单号 |
| FR-ORDER-02 | 订单快照 | P0 | 保存书名、成色、单价、买家昵称；后续修改书籍不影响历史订单 |
| FR-ORDER-03 | 幂等创建 | P0 | 请求头 `Idempotency-Key` 必填；24 小时内同 key 返回首次结果，不重复建单 |
| FR-ORDER-04 | 取消订单 | P0 | 待支付状态可由买家/管理员取消；释放书籍锁；通知双方 |
| FR-ORDER-05 | 超时取消 | P0 | 每 60 秒扫描；`CREATED` 超过 30 分钟自动 `CANCELLED`；重复执行安全 |
| FR-ORDER-06 | 订单列表/详情 | P0 | 支持全部/买入/卖出筛选；交易方或管理员可查看；展示状态、快照、支付、退款、状态流水 |
| FR-ORDER-07 | 状态机约束 | P0 | 非法转移返回 `409 ORDER_STATE_CONFLICT`；每次转移写审计日志 |
| FR-ORDER-08 | 自动关闭 | P1 | `COMPLETED` 满 30 天自动 `CLOSED`；关闭后不可评价 |

**订单状态**

| 状态 | 含义 | 可执行事件 |
|---|---|---|
| `CREATED` | 待支付 | `pay`、`cancel` |
| `PAID` | 已支付，待交接 | `ship`、`apply_refund` |
| `SHIPPED` | 待买家确认收货 | `confirm`、`apply_refund` |
| `COMPLETED` | 已完成，可评价 | `auto_close` |
| `CANCELLED` | 已取消 | 终态 |
| `REFUNDING` | 退款审批中 | `approve`、`reject` |
| `REFUNDED` | 已退款 | 终态 |
| `CLOSED` | 已关闭 | 终态 |

**幂等要求**

- 创建订单、申请退款、确认收货必须携带 `Idempotency-Key`。
- 同一用户同一 key 重复请求返回首次成功响应。
- 同一 key 用于不同接口返回 `409 IDEMPOTENCY_KEY_REUSED`。

### 5.4 支付（FR-PAY）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-PAY-01 | 支付方式 | P0 | 支持 `CAMPUS_CARD`（校内卡）与 `MOCK_THIRD_PARTY`（模拟第三方） |
| FR-PAY-02 | 支付校验 | P0 | 仅订单买家/管理员可支付；金额必须等于订单金额；订单必须为 `CREATED` 且在支付时限内 |
| FR-PAY-03 | 支付流水 | P0 | 每次成功支付生成唯一 `provider_txn_id`、渠道、金额、状态 |
| FR-PAY-04 | 退款流水 | P0 | 管理员同意退款后，原支付流水标记 `REFUNDED` |

**说明**：本期为模拟支付，支付请求同步返回成功并写流水，不对接真实网关，也不提供外部异步回调地址。

### 5.5 交接与确认收货（FR-HANDOVER）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-HANDOVER-01 | 交接点 | P0 | 下单时选择图书馆西门/宿舍楼下/校园快递点；卖家发货时可确认最终交接点 |
| FR-HANDOVER-02 | 生成交接码 | P0 | 卖家对 `PAID` 订单确认交接方式时生成 4 位数字交接码 |
| FR-HANDOVER-03 | 交接码可见性 | P0 | 只有卖家和管理员可读取；买家 API 返回 `null`，必须线下向卖家索取 |
| FR-HANDOVER-04 | 确认收货 | P0 | 仅买家/管理员可操作；必须输入正确交接码；订单 `SHIPPED` → `COMPLETED` |
| FR-HANDOVER-05 | 完成结算 | P0 | 确认收货后书籍 `SOLD`，买卖双方完成交易次数 +1 |

### 5.6 退款与纠纷（FR-REFUND）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-REFUND-01 | 未交接退款 | P0 | `PAID` 且支付未超过 48 小时可申请；填写原因 |
| FR-REFUND-02 | 交接后退款 | P0 | `SHIPPED` 且交接未超过 48 小时可申请；必须填写纠纷说明 |
| FR-REFUND-03 | 退款申请幂等 | P0 | 携带 `Idempotency-Key`，避免重复生成退款单 |
| FR-REFUND-04 | 管理员审批 | P0 | 同意 → `REFUNDED`；驳回 → `PAID`，均通知申请人 |
| FR-REFUND-05 | 退款后处理 | P0 | 同意退款：支付流水 `REFUNDED`，书籍 `OFF_SHELF`；驳回：交易继续 |

### 5.7 评价、信誉与举报（FR-REVIEW）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-REVIEW-01 | 双向评价 | P0 | 仅 `COMPLETED` 订单可评价；买家评卖家、卖家评买家；每人每单一次 |
| FR-REVIEW-02 | 评分与内容 | P0 | 评分 1–5 整数；内容必填 |
| FR-REVIEW-03 | 信誉分 | P0 | 被评价人信誉分更新为所有收到评价的平均分，保留两位小数 |
| FR-REVIEW-04 | 评价入口关闭 | P0 | `CLOSED` 订单不可再评价；`can_review=false` |
| FR-REVIEW-05 | 举报 | P1 | 登录用户可举报 `BOOK`/`REVIEW`/`USER`；必须填写原因；目标必须存在 |
| FR-REVIEW-06 | 举报处理 | P1 | 管理员可标记成立/驳回；书籍举报成立时书籍封禁；举报人收到结果通知 |

**说明**：页面目前只提供书籍举报入口；评价/用户举报通过 API 支持，页面入口列为后续迭代。

### 5.8 消息通知（FR-NOTICE）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|

## 6. 页面需求

| 页面 | 路径 | 核心内容 | 关键交互 |

**页面状态要求**

- 列表页：有数据、空数据、加载中、请求失败四种状态。
- 表单页：字段校验错误需在弹窗或 toast 中说明；提交按钮需防重复点击。
- 订单页：按钮必须由状态机当前状态的出口事件生成，不展示非法操作。
- 移动端：360px 宽度下可正常浏览与操作，导航可横向滚动。

## 7. 数据需求

### 7.1 数据表

| 表 | 作用 | 关键约束 |
|---|---|---|
| `users` | 用户 | 邮箱唯一、角色/状态 CHECK、bcrypt 哈希 |
| `categories` | 分类 | 名称唯一 |
| `books` | 教材 | 卖家/分类外键、价格 > 0、状态 CHECK |
| `orders` | 订单 | 订单号唯一、买卖双方/书籍外键、状态 CHECK、金额非负 |
| `order_events` | 订单审计 | 订单外键、记录 from/to/event/actor/note |
| `payments` | 支付流水 | `provider_txn_id` 唯一、渠道/状态 CHECK |
| `refunds` | 退款单 | 订单/申请人外键、状态 CHECK、处理说明 |
| `reviews` | 评价 | `(order_id, reviewer_id)` 唯一、评分 1–5 |
| `reports` | 举报 | 目标类型 CHECK、状态 CHECK |
| `notifications` | 站内信 | 用户外键、已读标记 |
| `idempotency_keys` | 幂等键 | `(user_id, key)` 主键、24 小时有效 |

### 7.2 数据规则

- 金额一律使用整数分（`INTEGER`），禁止浮点存储。
- 订单保存快照：`unit_price_snapshot`、`condition_snapshot`、`book_title_snapshot`、`buyer_nickname_snapshot`。
- 所有状态字段使用 CHECK 约束，禁止写入未定义状态。
- 时间统一存 UTC ISO 字符串（无时区后缀）；页面当前直接展示该字符串，部署在非 UTC 时区时应在展示层统一转换。
- 所有写操作在单个事务内完成；SQLite 使用 WAL + `BEGIN IMMEDIATE`。
- 上传文件只存相对文件名，实际文件位于 `app/static/uploads/`。

## 8. 接口需求

### 8.1 通用约定

- 前缀：`/api/v1`。
- 请求/响应：JSON；上传封面使用 `multipart/form-data`。
- 认证：HttpOnly 签名 Cookie。
- 金额字段：整数分，例如 `1800` 表示 ¥18.00。
- 时间字段：ISO 8601 字符串。
- 统一错误结构：

```json
{
  "code": "ORDER_STATE_CONFLICT",
  "message": "当前状态「已支付」不允许执行「取消订单」",
  "details": [{"field": "event", "reason": "PAID+cancel 不在状态转移表中"}],
  "trace_id": "a1b2c3d4"
}
```

| HTTP 状态 | 使用场景 |
|---|---|
| 200 | 查询/操作成功 |
| 201 | 创建成功 |
| 400 | 参数错误 |
| 401 | 未登录/会话失效 |
| 403 | 无权限、账号封禁 |
| 404 | 资源不存在或无权查看 |
| 409 | 状态冲突、重复锁书、幂等键冲突、重复评价 |
| 422 | 语义校验失败、交接码错误、退款窗口关闭 |

### 8.2 接口分组

| 分组 | 接口 |
|---|---|
| 健康检查 | `GET /health` |
| 分类 | `GET /categories` |
| 认证 | `POST /auth/register`、`POST /auth/login`、`POST /auth/logout`、`GET /auth/me`、`POST /auth/reset-password`、`POST /auth/password`、`PATCH /auth/profile` |
| 书籍 | `GET /books`、`POST /books`、`GET /books/{id}`、`PATCH /books/{id}`、`POST /books/{id}/actions/{event}`、`POST /books/{id}/cover` |
| 订单 | `POST /orders`、`GET /orders`、`GET /orders/{id}`、`POST /orders/{id}/pay`、`.../cancel`、`.../ship`、`.../refund`、`.../confirm` |
| 评价 | `POST /orders/{id}/reviews`、`GET /orders/{id}/reviews`、`GET /users/{id}/reviews` |
| 举报 | `POST /reports` |
| 通知 | `GET /notifications`、`GET /notifications/unread-count`、`POST /notifications/{id}/read`、`POST /notifications/read-all` |
| 后台 | `GET /admin/dashboard`、`GET /admin/books`、`GET /admin/refunds`、`POST /admin/refunds/{id}`、`GET /admin/reports`、`POST /admin/reports/{id}`、`GET /admin/users`、`POST /admin/users/{id}/status` |

### 8.3 幂等接口

以下接口必须携带 `Idempotency-Key` 请求头（建议 UUID）：

- `POST /orders`
- `POST /orders/{id}/refund`
- `POST /orders/{id}/confirm`

## 9. 非功能需求

### 9.1 性能

- 页面首屏在本地开发环境应在 1 秒内返回。
- 单机 SQLite 支持数十级并发读取；写操作通过 `BEGIN IMMEDIATE` 串行化。
- 本期不做 200 并发压测承诺；高并发需要迁移到 PostgreSQL/MySQL 并增加缓存。
- 书籍搜索使用 `LIKE`，数据量超过万级时应增加 FTS/搜索引擎。

### 9.2 安全

- 密码 bcrypt 哈希，禁止明文/可逆存储；登录/找回密码对不存在账号也执行一次哈希校验。
- 会话 Cookie：HttpOnly、SameSite=Lax；生产默认 Secure，支持会话有效期配置。
- 会话带 `session_version`：改密、找回密码、封禁/解封后旧 Cookie 立即失效。
- 写请求校验 `Origin` / `Sec-Fetch-Site`，跨站写请求返回 `403 CSRF_REJECTED`；未提供 Token 的 API 客户端不受影响。
- 所有 SQL 参数化；动态表名仅来自固定枚举。
- 订单、评价、通知、退款接口校验资源归属；交接码仅卖家/管理员可见。
- 登录、注册、找回密码、举报有进程内滑动窗口限流；单买家最多 3 笔待支付订单，降低恶意锁书风险。
- 请求体默认上限 3MB；上传封面另限 2MB，校验魔数并由服务端重命名。
- 生产环境强制 `BOOKRELAY_SECRET` 与管理员强口令，默认关闭演示数据与 API 文档，并拒绝已知默认管理员口令。
- 设置 CSP、HSTS（HTTPS）、X-Content-Type-Options、X-Frame-Options、Referrer-Policy、Permissions-Policy、Cache-Control: no-store。
- 当前未实现：CSRF Token、验证码/MFA、邮件/SMS 二次验证、审计日志外发。公网部署需配合阿里云 WAF/Nginx 限流与主机加固。

### 9.3 可用性与兼容性

- 支持主流现代浏览器：Chrome、Edge、Firefox、Safari 近两个大版本。
- 移动端最小宽度 360px；桌面端最大内容宽度 1120px。
- 表单控件有可见 label；状态颜色不作为唯一信息载体，同时显示文字。
- 不做 IE 兼容。

### 9.4 可维护性

- 领域层不依赖 FastAPI/SQLite，状态机可独立测试。
- 服务层封装事务、审计和通知，路由层保持轻薄。
- 所有状态枚举、错误码集中定义，禁止散落字符串。
- 自动化测试覆盖核心交易闭环；当前覆盖率约 85%。
- 修改业务规则必须同步更新本文档、`AGENTS.md`、`README.md` 和测试。

### 9.5 部署与运维

- 启动命令：`python run.py`，默认 `127.0.0.1:8000`。
- 数据库自动创建于 `data/bookrelay.db`；删除后重启自动重建种子数据。
- 生产建议单 worker 运行；反向代理提供 HTTPS；定期备份数据库。
- 基础访问日志输出到标准输出；后台定时任务异常写日志。

## 10. 验收场景

### 10.1 主流程验收

1. 学生 A 注册并登录。
2. 学生 A 发布《数据结构》，价格 ¥18.00，成色 9 成新。
3. 管理员登录后台，审核通过。
4. 学生 B 搜索“数据结构”，进入详情，选择图书馆西门下单。
5. 书籍变为 `LOCKED`；学生 B 在 30 分钟内完成模拟支付。
6. 学生 A 确认交接方式，系统生成 4 位交接码。
7. 学生 B 输入错误交接码，系统拒绝；输入正确交接码后订单 `COMPLETED`。
8. 学生 B 评价学生 A 5 星；学生 A 评价学生 B 5 星；双方信誉更新。
9. 订单满 30 天后自动 `CLOSED`，评价入口关闭。

### 10.2 异常验收

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-01 | 两个买家同时下单同一本书 | 仅一个成功，另一个 409 `BOOK_ALREADY_LOCKED` |
| AC-02 | 支付金额与订单不一致 | 422 `PAYMENT_FAILED`，订单仍 `CREATED` |
| AC-03 | 已支付订单执行取消 | 409 `ORDER_STATE_CONFLICT` |
| AC-04 | 已关闭订单提交评价 | 409 `ORDER_STATE_CONFLICT` |
| AC-05 | 买家直接读取交接码 | 返回 `null` |
| AC-06 | 封禁用户使用旧会话访问订单 | 旧会话失效（401/登录页）；重新登录返回 403 `ACCOUNT_BANNED` |
| AC-07 | 普通用户查询待审核书籍 | 403 |
| AC-08 | 买家申请退款后管理员驳回 | 订单回到 `PAID`，书籍仍锁定 |
| AC-09 | 交接后申请退款但不填纠纷说明 | 422 `VALIDATION_ERROR` |
| AC-10 | 重复使用同一幂等键创建订单 | 返回首次订单，不重复建单 |

### 10.3 自动化验收

```powershell
pip install -r requirements.txt
pytest -q
```

要求：

- 测试全部通过。
- 覆盖注册登录、完整交易闭环、退款同意/驳回、防重复锁书、超时取消、权限、后台处理、页面渲染。
- 至少包含封禁会话、交接码脱敏、关闭后评价、状态筛选越权等回归用例。

## 13. 术语表

| 术语 | 含义 |
|---|---|
| 锁书 | 下单后将书籍置为 `LOCKED`，防止被其他人购买 |
| 交接码 | 卖家发货时生成的 4 位数字，用于买家确认收货 |
| 交接点 | 图书馆西门、宿舍楼下、校园快递点 |
| 快照 | 下单时固化的书名、成色、价格、买家昵称 |
| 幂等键 | 客户端生成的唯一键，保证重复请求只执行一次 |
| 退款中 | 买家已申请退款，等待管理员审批 |
| 自动关闭 | 订单完成 30 天后进入 `CLOSED`，评价入口关闭 |
